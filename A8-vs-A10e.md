# Tab A8 vs A10e

**The tablet's column is filled**: every cell read from its own files; the how, with addresses, is in the [teardown](Tab-A8-teardown.md). The A10e column points at what's written up in [a10e-firmware](https://github.com/CassieFox23/a10e-firmware). The few things still unread are flagged at the foot of each teardown section.

![The two devices side by side: the A10e's single sboot image with its front stage encrypted loads and checks, its bootloader decides verified boot with libavb, and it boots stock Android 9 with OEM unlock refused; the Tab A8's seven stage files, none of the signed ones encrypted, load and ask Trusty, lk asks the secure world with command 0x20 and then sets the state, and it boots a LineageOS 22.2 GSI, unlocked, with the boot state orange](figures/a8-vs-a10e.png)

| Question | A10e (SM-A102U) | Tab A8 (SM-X200) |
|---|---|---|
| Chip family | Exynos | Unisoc UMS512 (`ro.soc.model=T618`) |
| Can the bootloader be unlocked? | No, OEM unlocking isn't allowed on that unit | Yes, done on two units from Download Mode, and `ro.boot.flash.locked` read back `0` after ([how-to](docs/lineageos-howto.md), step 5). The state is a 64-byte record in `miscdata` that the bootloader has the secure world judge; the permission switch is the last byte of `persistent` |
| What verified boot accepts | One Samsung key while locked | `vbmeta.img` is signed with one RSA-4096 key (a different one from the A10e's) and covers 11 partitions; the bootloader's signed certificate carries that key's SHA-256. On boot `lk` hands the image to the secure world (command `0x20`) and the boot state comes from that result; it also runs its own libavb, which checks the signature and feeds the kernel cmdline. Unlocked, `boot`/`recovery` skip the secure-world check and the state goes orange; a locked failure sets the red state (`3`) and `lk` drops into Download Mode (Odin) with a warning on screen rather than booting. See the [teardown](Tab-A8-teardown.md#what-lk-does-about-verified-boot) |
| Treble level vs a current GSI | Vendor level 3, below what the GSI ships | Vendor level 5, VNDK 30, kernel 4.14.199: the LineageOS 22.2 GSI ships a level 5 matrix and VNDK 30, so it fits |
| Secure world | TEEGRIS | **Trusty** (Google's little-kernel TEE, Unisoc's port), confirmed three ways: the kernel defconfig (`CONFIG_TRUSTY=y`, no `CONFIG_TZDEV`), the `trustos` image (a Trusty TOS built Oct 2023, with nine packed ELF blobs behind its kernel; its strings name keymaster, gatekeeper, RPMB storage and Widevine among others, but which blob is which wasn't read), and what it does with the bootloader's two SMC commands.<br><br>`0x33` authenticates an unlock token Trusty computes for itself - AES-CBC over the `VerifiedBoot-UNLOCK` label, keyed by what the `VerifiedBoot-HUK-DERIVE` label says is the chip's hardware key, so tied to the chip if that label holds. `0x20` runs libavb (`avb_slot_verify`) inside the TEE. The stack looks like lk → a BL31 monitor (`sml`, by its strings) → Trusty, though what BL31 does between the `smc` and Trusty wasn't read.<br><br>The SELinux fence holds: 0 permissive domains, no app domain reaches the `teetz_device` IPC node (mode `0660 system:system`, so Unix perms back it up, unlike the A10e's `0666`), and of the HALs that touch the TEE, an app can `find` only the media ones (Widevine and the codec), never the key ones; keys go through `keystore` → keymaster as normal |
| Extra flash gates | Knox Guard | Knox Guard here too: flashing is blocked when its state is `LOCKED` and a function (`0x9f037540`) that bitmask-tests a flags global at `0x9f45b290` returns `0`, and unlocking is refused in `PRENORMAL`, `ACTIVE`, `LOCKED` or `ERROR` |
| Ends up running | Stock Android 9 | LineageOS 22.2 (Android 15) as a GSI on the stock 4.14.199 kernel; both read back right after the flash, Oct 2026. The Android 11 vendor is still stock going by what was flashed (only `system` and `recovery`) |

The A10e answers are short on purpose. The real ones, with addresses, are in its [teardown](https://github.com/CassieFox23/a10e-firmware/blob/master/A10e-teardown.md).
